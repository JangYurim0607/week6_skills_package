# A vs B 비교 (v2: PDF 결과물)

같은 입력(`data/roblox_games.csv`, `data/game_notes.md`)과 같은 명세(`data/task_spec.md`)로, A는 스킬 없이, B는 `B_skills/skills/` 8개를 읽고 따라서 만들었다. 각각 별도의 에이전트가 만들었고 A는 B 폴더를 볼 수 없게 했다.

## 눈에 띄는 차이

- **구조**: B는 검색 의도 분류(스킬의 분류 + 숏츠용 '오락형' 추가), 토픽 클러스터, 플랫폼별 배치 근거(Reels 15~30초라 제외, TikTok은 30초 이내 편 위주 등)가 들어갔다. A는 같은 항목을 명세대로 채웠지만 플랫폼 근거가 얇다.
- **스토리보드 분량**: B는 편마다 첫 3초 훅(화면·낭독·자막을 따로 적음)과 후처리 체크리스트까지 있어서 더 길다. A는 편당 2쪽으로 간결하다.
- **게임 선택**: 두 쪽 모두 조사 노트가 있는 게임만 골랐다. B는 노트가 없는 +1 Speed Keyboard Escape를 원래 스크립트가 2위로 뽑는 것을 걸러냈다(스킬 때문이 아니라 사실 규칙 때문).
- **사실 정확도**: 둘 다 노트·CSV 밖의 게임 내용을 사실처럼 쓰지 않는 것을 목표로 했고 B는 `fact_check.py`로 확인했다. A는 그런 자동 검사 없이 눈으로 확인했다. 내가 둘 다 전수 검증한 것은 아니다.
- **수정한 오류**: 노트의 Brookhaven 누적 방문수를 "80억 4천만"으로 잘못 적어서(정확히는 804억) 두 PDF 모두 "10배 불일치"라는 잘못된 문장이 들어갔고, 노트와 두 PDF를 고쳤다.

## 한계 (솔직하게)

- 한 번씩만 만들었다. 같은 모델이 만든 한 쌍의 결과라서 차이가 우연일 수 있다.
- 조회수 같은 실제 성과는 재지 않았다. "B가 더 낫다"는 증거가 아니라 "구조가 다르다"의 기록이다.
- 한국어 슬롭 검사(`ko_slopcheck.py`)는 대사만 대상으로 설계했는데, 이번 PDF는 표와 레이아웃 텍스트가 섞여 있어 PDF 텍스트를 통째로 돌린 점수(A 19, B 35)는 공정한 비교가 아니다. 그래서 점수 비교는 결론에 쓰지 않는다. 금지 패턴 적중은 둘 다 0건이었다.
- 영어 기반 도구(`slopcheck.py`, `hookscore.py`)는 한국어에 쓸모가 없었고, B의 훅 점수는 영어 번역으로 대신 본 것이라 PDF에는 넣지 않았다.
- B 에이전트는 독립 검토자(서브에이전트)를 못 썼고, `ai-video-storyboard`가 참조하는 파일 4개는 폴더에 없었다.
- 스킬은 대부분 영어·SEO·AI 영상 생성 전제라서, 한국어 숏츠 녹화용으로는 직접 만든 `roblox-shorts-ko`와 검사기가 필요했다.
