# 스킬 사용 기록

각 스킬의 `SKILL.md`(필요하면 참조 파일)를 읽고 적용했습니다. 스킬 파일은 수정하지 않았습니다. 아래는 스킬별로 "그 스킬 때문에 결과물에서 구체적으로 달라진 것"과 "별 도움이 안 된 것"을 구분해 적은 기록입니다. 스킬을 실제로 읽고 실행한 순서대로 정리했습니다.

## 실행한 명령과 저장 위치 (모두 `output/artifacts/`)

| 명령 | 결과 파일 |
|---|---|
| `scripts/keyword_analysis.py --csv ../data/roblox_games.csv --out output/artifacts` | `keywords.csv`, `cluster_summary.md`, `top_picks.json`, `keyword_analysis_stdout.txt` |
| `skills/yt-script/hookscore.py` 게임별 한국어 훅 5개 | `hookscore_{brookhaven,speed,adoptme}_ko.txt` |
| 같은 훅의 영어 번역본 5개 | `hookscore_{brookhaven,speed,adoptme}_en.txt` |
| 수정한 Brookhaven 훅 재채점 | `hookscore_revised_brookhaven_{ko,en}.txt` |
| `scripts/ko_slopcheck.py` (대사만 / 파일 전체) | `ko_slopcheck_spoken_only.{txt,json}`, `ko_slopcheck_scripts_full.txt` |
| `skills/anti-ai-slop/scripts/sanitize.py` (복사본에 실행) | `aislop_sanitize_{spoken,full}.json` |
| `skills/anti-ai-slop/scripts/slopcheck.py` | `aislop_slopcheck_{spoken,full}.{txt,json}` |
| 나쁜 한국어 문장으로 만든 대조 실험 | `negative_control_ko_slop.md`, `negative_control_aislop_slopcheck.txt`, `negative_control_ko_slopcheck.txt` |

`scripts/ko_slopcheck.py`와 `skills/roblox-shorts-ko/scripts/ko_slopcheck.py`는 `diff`로 확인했을 때 같은 파일이었습니다. 대사 줄만 뽑은 파일이 `spoken_only.txt`입니다. `[화면: ...]` 태그와 표, 메모를 빼고 사람이 읽는 대사만 검사하려고 만들었습니다.

실행하지 않은 것: `grade.py`(다른 모델 패널)는 API 키 설정이 없어서 못 했고, `detect.py`는 원고를 외부로 보내서 하지 않았습니다. `references/reviewer.md`가 말하는 "새 서브에이전트에게 검토 맡기기"도 이 환경에 서브에이전트 도구가 없어서 못 했습니다. 대신 스킬이 허용한 대로 직접 한 번 처음 보는 사람처럼 다시 읽었습니다. 이 점수와 검토는 독립 검증이 아닙니다.

## 1. seo-keyword-research

달라진 것
- `keyword_analysis.md`의 뼈대가 이 스킬의 출력 형식을 따랐습니다. 의도별 개수 표, 클러스터 표, 키워드 맵, 발행 순서 순서입니다.
- 스킬의 4분류 의도 중 navigational이 스크립트에 없다는 점을 이 스킬을 읽고서야 알아챘고, 분석 파일에 빈틈으로 적었습니다.
- 스킬이 "의도는 SERP로 검증하라"고 하는데 할 수 없어서, 의도 라벨이 템플릿 값이라는 단서를 분석 파일에 썼습니다.
- 우선순위 공식(검색량 x CTR x 사업 가치 / 난이도)을 쓰지 않고 "입력이 없어서 계산하지 않았다"고 적었습니다. 값을 만들어 채우지 않았습니다.

별 도움이 안 된 것
- 이 스킬은 SaaS 웹사이트 SEO용입니다. GSC, DataForSEO, KD 구간표, 백링크 기준, URL 키워드 맵, 퀵윈 정의가 모두 전제하는 데이터가 이 과제에는 없습니다. 쓸 수 있었던 건 의도 분류 개념, 클러스터 개념, 맵 형식 정도입니다.
- 시드 확장 기법 6개 중 이 환경에서 가능한 것은 수식어 붙이기뿐이었고, 그것도 `keyword_analysis.py`가 이미 하고 있었습니다.

## 2. social + references/short-form-video.md

달라진 것
- 플랫폼 길이 기준(틱톡 15~60초, 쇼츠 30~60초)을 보고 대본 길이를 쇼츠 하한 30초 이상으로 잡았습니다. 과제는 25~40초이므로 25~29초대는 피했습니다.
- "3초 안에 화면, 대사, 자막 훅이 동시에" 규칙 때문에 모든 훅 비트에 `[화면: ... / 자막: ...]`를 넣었습니다. 자막도 대사와 다른 짧은 명사구로 썼습니다.
- 자막은 최대 2줄, 한 줄 3~5단어라는 기준에 맞춰 자막 문구를 짧게 줄였습니다("방문수 834억", "2위, 6/10 집계").
- CTA를 행동 하나로 제한했습니다(댓글 2편, 팔로우 1편).

별 도움이 안 된 것
- 훅 라이브러리(Secret, Hack, Controversial 등)는 영어 템플릿이고 B2B/SaaS 예시가 많아서 문장은 쓰지 못했습니다. 질문형과 숫자형이라는 유형만 참고했습니다.
- 올리는 시간대, 업로드 빈도 표는 한국 시장 데이터가 아니라서 가져오지 않았습니다.

## 3. yt-script (hooks.json, hookscore.py)

달라진 것
- 훅을 게임당 5개 써서 점수를 매기고 상위 2개를 남기는 절차를 그대로 했습니다. 각 대본 끝에 5개 훅과 점수 표를 넣었습니다.
- "숫자를 지어내지 말고, 모르면 비워라"는 규칙 때문에 촬영해야 아는 값은 `[촬영 후 입력]`, `[단계 입력]`, `[초 입력]` 같은 빈칸으로 두었습니다. 대본 2와 3의 결과 비트가 이 때문에 빈칸을 갖습니다.
- 훅 비트 다음에 "무엇을 할지 한 문장으로 말하고 바로 시작한다"는 구조를 따라, 인사나 채널 소개를 전혀 넣지 않았습니다.
- 모든 비트에 화면 지시를 달았습니다(`[ON SCREEN]`을 `[화면]`으로 옮김).

hookscore.py를 한국어에 쓴 결과는 쓸 만하지 않았습니다.
- 한국어 훅 15개의 점수는 25~37점입니다. 모두 WEAK이고 차이는 거의 잡음입니다. 이 스크립트는 `[a-z0-9]`만 단어로 세기 때문에 한글 단어는 0개로 계산됩니다. 점수를 가른 것은 훅에 들어 있는 영문 게임 이름과 숫자였습니다. 예를 들어 "+1 Speed Keyboard Escape는 ... 출처에 없어요"가 37점으로 1위를 한 것은 영문 이름이 많아서입니다.
- 그래서 훅을 영어로 번역해서 다시 채점했습니다. 이건 임시 방편입니다. 번역본도 15개가 전부 WEAK(30~54점)이었습니다. 이 채점기는 "you"로 시청자를 부르는 정도, 위험을 뜻하는 단어, 유튜브 롱폼 기준 길이(9~24단어)를 봅니다. 데이터를 말하는 내 훅은 구조상 점수가 낮게 나옵니다. 스크립트 문서에도 같은 설계 한계가 적혀 있습니다("한 크리에이터의 히트와 미스를 거의 가르지 못한다").
- 점수가 선택을 바꾼 정도: Adopt Me!는 번역본 1위(52점)를 골랐습니다. Brookhaven은 상위 2개 중 2위(47점)를 길이 때문에 골랐습니다. +1 Speed는 1위 훅("방문수는 출처에 없어요")이 시청자와 무관한 문장이라 버리고 2위를 골랐습니다. 세 편 중 점수 1위와 선택이 일치한 건 한 편뿐입니다. 점수는 판단을 대신하지 못했고 후보를 비교해 보는 계기 정도였습니다.
- Brookhaven 훅은 마지막에 "이 게임 모르면 로블록스 얘기에 못 껴요"(47점)를 지우고 "동접 1위 로블록스 게임, 누적 방문수가 834억이에요"(37점)로 바꿨습니다. 앞 문장은 근거가 없는 주장이었습니다. 점수는 10점 내려갔고 그대로 두었습니다.
- 스킬의 마지막 규칙("ship it, or change it?"로 끝내기)은 이 파이프라인 형식과 맞지 않아 적용하지 않았습니다.

## 4. yt-shorts

이 스킬은 긴 영상의 자막에서 쇼츠 구간을 잘라 내는 용도입니다. 이번 과제에는 원본 영상이 없어서 대부분 적용하지 못했습니다.

달라진 것은 두 가지입니다.
- 첫 줄과 다른 문구를 첫 2초 화면 자막에 쓰는 규칙(예: 대사 "동접 1위 ... 834억", 자막 "방문수 834억"은 같은 숫자지만 대사 전체를 반복하지 않음).
- 마지막 줄이 첫 줄로 이어지는 루프 포인트를 대본마다 한 줄 적었습니다. 솔직히 이 루프 문장들은 억지스럽습니다. 대본 1의 루프는 "댓글을 고정해 둔다"는 운영 메모에 가깝고 영상 안에서 실제로 루프를 만들지는 않습니다.

세로 프레임에서 잘려 나가는 부분 점검은 해당 사항이 없어서 하지 않았습니다.

## 5. ai-video-storyboard

이 스킬은 AI 영상 생성기에 넣을 컷별 영어 프롬프트(색 팔레트, 렌즈, "cinematic 1080p, synchronized audio")를 만드는 용도입니다. 로블록스 숏츠는 화면 녹화라서 그 부분은 쓰지 않았습니다.

달라진 것은 하나입니다. "30초 틱톡은 6컷, 훅 - 전개 - 결과 - CTA"라는 표를 보고 대본을 6비트로 나눴습니다. 대본 3편 모두 훅 1, 전개 2, 결과 2, CTA 1입니다. 이것 말고 이 스킬이 대본 내용에 준 영향은 없습니다. 비트 6개 구성도 다른 스킬만으로 만들 수 있는 정도입니다.

## 6. roblox-shorts-ko

이 스킬이 한국어 결과물에 가장 많이 영향을 줬습니다.

달라진 것
- 톤: 해요체 중심에 "너는 ~해?" 같은 반말을 섞었습니다. 대사 한 줄 평균 21.6자입니다(스킬 기준 25자 안팎보다 약간 짧음).
- 첫 문장에 결과나 궁금증을 던지게 했습니다. 인사, 채널 소개, 게임 설명으로 시작하는 대본이 없습니다.
- 숫자 규칙: 대본의 모든 숫자는 CSV에서 가져왔고 "6월 10일 기준"을 붙였습니다. 근거 없는 수치 자리는 `[수치 확인 필요]` 대신 같은 취지의 `[촬영 후 입력]` 빈칸으로 처리했습니다.
- 로블록스 용어와 게임 이름 영문 표기 유지(Brookhaven RP, Adopt Me!).
- "여러분", 광고 멘트, 접속어를 쓰지 않았습니다. 처음부터 금지 목록을 보고 썼기 때문입니다.
- `ko_slopcheck.py` 결과: 대사만 검사하면 첫 실행부터 0점, 금지 패턴 적중 없음이었습니다. 쓰기 전에 규칙을 읽고 썼으니 당연한 결과이고, 검사기가 대사를 고친 것은 아닙니다. 검사기가 실제로 잡은 것은 대본 파일 전체를 돌렸을 때 내가 쓴 설명 문장 하나("점수가 아니라 내 판단") 뿐이었고, 그 문장은 고쳤습니다. 파일 전체 점수는 31점에서 23점으로 내려갔고, 남은 점수는 설명 문장이 45자를 넘는 데서 나옵니다(대본이 아니라 메모).
- 한계: `ko_slopcheck.py`는 문자열 목록에 걸리는지만 봅니다. 0점은 "금지된 문자열이 없다"는 뜻이지 대본이 좋다는 뜻이 아닙니다.
- 스킬은 훅 후보 3개를 쓰라고 하고 `yt-script`는 5개를 쓰라고 합니다. 5개를 썼습니다.

## 7. anti-ai-slop

달라진 것 (원칙 부분)
- "Never invent"와 "Cite or cut": 이유를 지어내서 채우던 문장을 빈칸으로 바꾸고, 근거 없는 "모르면 못 껴요"를 지웠습니다. 이 스킬의 규칙 중 이번 결과를 바꾼 것은 사실상 이 두 가지입니다.
- "Drop the foil"과 negative parallelism: "슈팅도 서바이벌도 아니고 역할놀이예요" 훅은 점수가 가장 낮았고(30점) 선택하지 않았습니다. 설명 문장 "A가 아니라 B" 하나도 고쳤습니다.
- 마지막에 읽으면서 시제를 맞췄습니다. 스냅샷 값("동접은 ~쯤이에요")이 "이었어요"와 섞여 있어서 모두 과거형으로 통일했습니다.

스크립트 결과
- `sanitize.py`: 보이지 않는 문자 0개, 변경 없음.
- `slopcheck.py`: 대사만 100점, 전체 파일 99점(영어 제목 대소문자 규칙 F7이 한글+영문 게임명 제목에 걸린 1건, 심각도 note). 겉으로는 통과입니다.
- 이 통과는 한국어에서 의미가 없습니다. 대조 실험으로 금지 표현을 일부러 몰아 쓴 한국어 문단("오늘은 ... 다양한 ... 알아보겠습니다 ... 놓치지 마세요!")을 넣었더니 `slopcheck.py`는 100점, `ko_slopcheck.py`는 60점에 13건을 잡았습니다. 같은 `slopcheck.py`가 이 패키지의 영어 슬롭 예시 파일에는 0점(F)을 줬습니다. 즉 영어 규칙 세트(`rules.json`의 영어 단어, 구문 목록)는 한국어 문장을 아예 보지 못합니다.
- 결론: anti-ai-slop의 스크립트 검사는 이 한국어 대본에 거의 쓸모가 없었습니다. 이 스킬에서 쓸모 있었던 것은 스크립트가 아니라 원칙(지어내지 않기, 근거 없는 주장 지우기, 구체성) 쪽입니다.
- 서브에이전트 검토와 외부 패널은 실행하지 못했습니다. 위 "실행하지 않은 것"을 참고하세요.

## 8. humanizer

달라진 것
- §1(not X but Y)이 한국어에도 같은 모양("A가 아니라 B")으로 나온다는 설명을 보고, 한국어에 대해서는 `ko_slopcheck.py`의 반전 문형 패턴과 같이 적용했습니다. 위의 설명 문장 수정이 이 경우입니다.
- §7(문장 시작 반복)과 §6(삼단 나열)을 한국어 대사에서 확인했습니다. 삼단 나열은 없었습니다. 문장 시작 반복은 있었습니다. 세 대본이 모두 "6월 10일 기준 N위 - 동접 N명 - 장르 표기" 순서의 같은 골격으로 전개됩니다. 시리즈 형식으로 통일한 면도 있지만 읽으면 틀에 박혀 있습니다. 시제만 통일하고 골격은 그대로 두었습니다. 남은 문제로 적어 둡니다.
- §17(근거 없는 권위)과 §13(과장)을 훅에 적용해 "모르면 못 껴요"를 지웠습니다. 이건 anti-ai-slop 원칙과 겹칩니다.

별 도움이 안 된 것
- 이 스킬 본문 26개 패턴 대부분은 영어 표현이 전제입니다. 대시(§8), 굵은 글씨(§19), 곡선 따옴표(§21), 하이픈 쌍(§10), AI 단어 목록(§12), 챗봇 잔재(§22)는 구어체 한국어 대사에 거의 해당하지 않았습니다. 영어 예시를 한국어로 옮겨 판단해야 해서 매번 번역이 필요했고, 실제로 바뀐 줄은 위에 적은 것뿐입니다.

## 정리

- 결과물에 실질적으로 영향이 컸던 것: `roblox-shorts-ko`(톤과 금지 패턴, 빈칸 처리), `yt-script`의 "숫자를 지어내지 않는다"와 5개 훅 비교 절차, `social`의 길이와 3초 규칙, `seo-keyword-research`의 문서 구성.
- 영향이 작았던 것: `yt-shorts`(원본 영상 없음), `ai-video-storyboard`(6비트 구분 정도), `humanizer`(원칙 일부만).
- 한국어에서 사실상 쓸모없었던 도구: `hookscore.py`(한글을 단어로 세지 못함, 번역본도 전부 WEAK), `anti-ai-slop/scripts/slopcheck.py`(영어 규칙이라 나쁜 한국어도 100점). 둘 다 통과나 점수를 근거로 삼을 수 없습니다.
- 한국어에서 유일하게 의미 있는 자동 검사는 `ko_slopcheck.py`지만 금지 문자열 목록 일치만 봅니다.
- 이 파이프라인의 대본은 결과 비트에 촬영 후 채울 빈칸을 갖습니다. 촬영하지 않고는 값을 알 수 없고, 지어내지 않기로 한 결과입니다.
